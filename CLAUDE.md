# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Java SDK for the Definancy API. Multi-module Maven project (parent + `core` + `demos`). Java 8 is the production runtime (TIBCO BW5, WebSphere v9.5); JDK 11/17/21 also tested via the strict-Java8 profile. The generated client uses the Jersey-2 transport (provided-scope, not bundled in the shaded jar). The hand-written domain layer mirrors the TypeScript SDK at `../typescript/sdk/`.

## Commands

```bash
mvn -B package                      # build both modules + run tests + shaded core jar
mvn -B package -DskipTests          # faster, same artifacts
mvn -B test                         # run unit tests + conformance Runner
cd demos && mvn -B exec:java \
  -Dexec.mainClass=com.definancy.sdk.demo.<DemoClass> \
  -Dexec.classpathScope=test
```

## Code Generation

`core/src/main/java/com/definancy/{api,model,...}` is auto-generated by `openapi-generator` (jersey2 library, v7.20.0). Don't hand-edit — those files are clobbered on every regenerate.

To regenerate:

```bash
cd ../../..   # factory root
task gen:java
```

The `core/.openapi-generator-ignore` file lists hand-owned files protected from regeneration. See `../../../languages/java/OVERRIDES.md` for the full discipline (active overrides, hand-owned generator outputs, provided-scope dependency rationale).

## Architecture

```
.
├── pom.xml                  ← parent (packaging=pom)
├── core/                    ← the SDK
│   ├── pom.xml              ← shaded jar build, full-distribution profile
│   └── src/main/java/com/definancy/
│       ├── api/             ← generated: API interfaces (per-tag)
│       ├── model/           ← generated: request/response models
│       └── sdk/             ← hand-written domain layer (NEVER generated)
│           ├── auth/        ← DPoP + Authorization JWT + AuthProvider
│           │   ├── impl/    ← LocalAuthProvider implementation
│           │   ├── DPoP.java, Authorization.java, ...
│           │   ├── Jwt.java, Jwk.java, AuthProvider.java
│           │   └── AuthRequestFilter.java   (JAX-RS request filter)
│           ├── crypto/      ← Ed25519PublicKey, KeyPair
│           ├── util/        ← Encoder (Base32/Base64url), Digester (SHA),
│           │                  CryptoProvider (BC bootstrap)
│           ├── AmountMath.java, ID.java, DID.java
└── demos/                   ← runnable mains (separate jar, not shipped)
    └── src/main/java/com/definancy/sdk/demo/
```

**Layering principle:** generated wire layer at `api/` + `model/` (regenerable). Hand-written domain layer at `sdk/` (auth, crypto, identity, amount math) — must stay green against `conformance/vectors/*` from the factory.

## Key Patterns

- **Dual JWT auth.** Each authenticated request carries `Authorization: DPoP {auth-jwt}` (caller identity via DID + JWK thumbprint) and `DPoP: {dpop-proof}` (key possession + body hash). Mirrors the TS SDK's middleware pattern. Wired via `AuthRequestFilter` (JAX-RS `ClientRequestFilter`).
- **AuthProvider interface.** Pluggable auth strategy. `auth/impl/LocalAuthProvider` signs locally with a `KeyPair`; HSM/remote-signer implementations slot in via the same interface.
- **Signer interface.** Abstraction over signing — `KeyPair` is the default Ed25519 implementation backed by BouncyCastle.
- **Identity types.** `ID` (32-byte Ed25519 public key + SHA-512/256 checksum, Base32-encoded to 58 chars). `DID` (`did:definancy:{network}:{id}`).
- **`KeyPair.generateKeyPairFromSecret(byte[])`** — deterministic key generation from a base64url-encoded 32-byte seed. Mirrors TS's `KeyPair.fromSecret(secret)`.
- **Provided-scope dependencies.** Jersey, JAX-RS, HK2, BouncyCastle, Apache HttpClient — all NOT bundled in the shaded jar. Deployment platforms (BW5, WebSphere v9.5) ship them as shared libraries. See `../../../languages/java/OVERRIDES.md` "Provided-scope dependencies" for the version-pinned consumer install list.
- **JDK 8 floor.** Production runtime is Java 8. The build also runs on JDK 11/17/21 — those auto-activate the `strict-java8-on-jdk9plus` profile that enforces the Java 8 API surface via `<release>8</release>`. Local JDK 8 builds use `<source>/<target>=1.8`.
- **Jackson canonical JSON.** JWT payload canonicalization uses sorted-key Jackson serialization to byte-match the TS SDK's output for cross-language conformance.
- **Conformance Runner** lives at `core/src/test/java/com/definancy/sdk/conformance/Runner.java`. Run via `task conformance:java` from the factory root, or `mvn test` from this repo (Runner is JUnit-discovered).

## TypeScript SDK Reference

The TypeScript SDK at `../typescript/sdk/src/` is the cross-language sibling. When adding a feature, check the TS implementation for behavior parity — especially auth flow, ID encoding, JWK thumbprint computation, and JWT canonicalization. Conformance vectors enforce byte-identical output between the two.
