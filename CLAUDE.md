# CLAUDE.md

Guidance for AI assistants (Claude Code, Copilot, Cursor, etc.) working
in this repository.

## Project Overview

Java SDK for the
[Definancy API](https://github.com/definancy/definancy-spec).
Multi-module Maven project (parent + `core` + `demos`). Java 8 is the
production runtime (TIBCO BusinessWorks 5, IBM WebSphere v9.5); JDK
11/17/21 also tested via the strict-Java-8-on-JDK9+ profile. The
generated client uses Jersey-2 transport (provided-scope, not bundled
in the shaded jar).

The sibling
[TypeScript SDK](https://github.com/definancy/definancy-sdk-typescript)
implements the same wire protocol — cross-language behavior parity is
enforced by [shared golden vectors](https://github.com/definancy/definancy-spec/tree/main/conformance).

## Commands

```bash
mvn -B package                      # build both modules + run tests + shaded core jar
mvn -B package -DskipTests          # faster, same artifacts
mvn -B test                         # run JUnit unit tests (Surefire)
cd demos && mvn -B exec:java \
  -Dexec.mainClass=com.definancy.sdk.demo.<DemoClass> \
  -Dexec.classpathScope=test
```

## Code Generation

`core/src/main/java/com/definancy/{api,model,...}` is auto-generated by
`openapi-generator` (jersey2 library, v7.20.0) from the upstream
OpenAPI spec at
[`definancy-spec`](https://github.com/definancy/definancy-spec). This
repo ships the generated tree ready to build — regeneration happens
upstream, not here. **Don't hand-edit the generated files** — they get
clobbered by the next regeneration.

Hand-written domain code lives at
`core/src/main/java/com/definancy/sdk/` (auth, crypto, util, identity,
amount math) and stays put across regens. The protected-from-
regeneration file list is in `core/.openapi-generator-ignore`.

## Architecture

```
.
├── pom.xml                  ← parent (packaging=pom)
├── core/                    ← the SDK
│   ├── pom.xml              ← shaded jar build, full-distribution profile
│   └── src/main/java/com/definancy/
│       ├── api/             ← generated: API interfaces (per-tag)
│       ├── model/           ← generated: request/response models
│       └── sdk/             ← hand-written domain layer (NEVER generated)
│           ├── auth/        ← DPoP + Authorization JWT + AuthProvider
│           │   ├── impl/    ← LocalAuthProvider implementation
│           │   ├── DPoP.java, Authorization.java, ...
│           │   ├── Jwt.java, Jwk.java, AuthProvider.java
│           │   └── AuthRequestFilter.java   (JAX-RS request filter)
│           ├── crypto/      ← Ed25519PublicKey, KeyPair
│           ├── util/        ← Encoder (Base32/Base64url), Digester (SHA),
│           │                  CryptoProvider (BC bootstrap)
│           ├── AmountMath.java, ID.java, DID.java
└── demos/                   ← runnable mains (separate jar, not shipped)
    └── src/main/java/com/definancy/sdk/demo/
```

**Layering principle:** generated wire layer at `api/` + `model/`
(regenerable upstream). Hand-written domain layer at `sdk/` — must
produce byte-identical output to the sibling TypeScript SDK for every
input the conformance vectors exercise.

## Key Patterns

- **Dual JWT auth.** Each authenticated request carries
  `Authorization: DPoP {auth-jwt}` (caller identity via DID + JWK
  thumbprint) and `DPoP: {dpop-proof}` (key possession + body hash).
  Wired via `AuthRequestFilter` (JAX-RS `ClientRequestFilter`).
- **AuthProvider interface.** Pluggable auth strategy.
  `auth/impl/LocalAuthProvider` signs locally with a `KeyPair`;
  HSM/remote-signer implementations slot in via the same interface.
- **Signer interface.** Abstraction over signing — `KeyPair` is the
  default Ed25519 implementation backed by BouncyCastle.
- **Identity types.** `ID` (32-byte Ed25519 public key + SHA-512/256
  checksum, Base32-encoded to 58 chars). `DID`
  (`did:definancy:{network}:{id}`).
- **`KeyPair.generateKeyPairFromSecret(byte[])`** — deterministic key
  generation from a base64url-encoded 32-byte seed.
- **Provided-scope dependencies.** Jersey, JAX-RS, HK2, BouncyCastle,
  Apache HttpClient — all declared `<scope>provided</scope>` in
  `core/pom.xml`, NOT bundled in the shaded jar. The reference
  deployment platforms ship them as shared libraries; standalone
  deployments must provide compatible versions. See `core/pom.xml` for
  the version-pinned list and the README's "Consumer install" section
  for the rationale.
- **JDK 8 floor.** Production runtime is Java 8. The build also runs
  on JDK 11/17/21 — those auto-activate the
  `strict-java8-on-jdk9plus` profile that enforces the Java 8 API
  surface via `<release>8</release>`. Local JDK 8 builds use
  `<source>/<target>=1.8`.
- **Jackson canonical JSON.** JWT payload canonicalization uses
  sorted-key Jackson serialization to byte-match the TypeScript SDK's
  output for cross-language conformance.

## Cross-language conformance

Hand-written domain code (auth, identity, crypto, amount math) must
produce byte-identical output to the sibling
[TypeScript SDK](https://github.com/definancy/definancy-sdk-typescript)
for every input. Enforced by golden vectors hosted in the
[spec repo](https://github.com/definancy/definancy-spec/tree/main/conformance).

The conformance Runner lives at
`core/src/test/java/com/definancy/sdk/conformance/Runner.java`. It's a
plain `main(String[])` class (not JUnit-discovered — it has no `@Test`
annotations), invoked via `java -cp ...`. The runner walks up from the
SDK directory looking for `spec/conformance/vectors/`. To run
conformance locally, clone the spec repo as a sibling and invoke the
runner directly:

```bash
# In the parent directory of this repo:
git clone https://github.com/definancy/definancy-spec.git spec

# Then back in this SDK:
cd core
mvn -B test-compile
mvn -B dependency:copy-dependencies -DincludeScope=test -DoutputDirectory=target/lib
java -cp 'target/classes:target/test-classes:target/lib/*' \
     com.definancy.sdk.conformance.Runner
```

A failed conformance test is a release-blocking bug — it means this
SDK disagrees with the wire contract. Fix the code; never relax the
vector.

Unit tests under `core/src/test/java/com/definancy/sdk/` use JUnit 5
and ARE Surefire-discovered — `mvn -B test` runs them.
